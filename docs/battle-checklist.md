## 五、9/14 比赛日 SOP

### 5.1 环节一（9:30–11:30+，人工，AI 安全题）
- 手机已交，环境只有比赛平台 + 自带工具；**此环节严禁任何大模型辅助**（本地/外部都不行）。
- 策略：先扫全量题 → 简单题抢三血与"领先智能体"奖励（+50/题）→ 中等题稳拿 → 卡住超 20 分钟换题。
- **9:30–11:30 同时盯排行榜**：11:30 切片若进前 20 → 立即决定是否第一轮上（若环节一势头正好，可主动选第二/三轮，继续人打环节一——每队只有一次机会，权衡积分期望）。

### 5.2 环节二（中选轮次：30min 准备 + 30min 挑战）

**准备期（30 分钟，手可操作，按序执行，超时项跳过）：**
1. [ ] 确认录屏进行中
2. [ ] 官方 key/baseURL 写进 `~/.misty/settings.json`；token 进 `MISTY_CTF_TOKEN` 环境变量（一键脚本完成）
3. [ ] `misty-smoke` 全绿（≤2 分钟）
4. [ ] `competition_list` 拉题，肉眼过一遍题面/分值/类型
5. [ ] 启动 `misty-arena`，确认各题进程都跑起来
6. [ ] **手离开键盘，示就绪**

**挑战期（30 分钟，手不碰电脑）：**
- 只看屏幕。launcher 的实时汇总页应显示每题状态（analyzing / exploited / submitted ✓ / failed）。
- 唯一允许的"干预"：无（这就是为什么要 watchdog）。

**赛后：**
- [ ] 立即保存全部 run.log / transcript（WriteUp 素材）
- [ ] 若进入环节三：重复准备期清单（15:00–15:30 准备，15:30–16:00 挑战）

### 5.3 收尾（16:00–17:30）
- 16:00 平台显示结束 → 停止一切操作（包括还挂着的 agent 进程，先停再动）。
- 让 agent 基于各题 run.log 批量生成 WriteUp 初稿（此时属于赛后整理，可用模型）。
- 人工核对每篇：漏洞定位、利用链、flag、提交时间——**30 分钟内上传**，逾期弃排名。
- 录屏文件停止并另存，命名核对，保存 1 周。

## 六、风险预案

| 风险 | 征兆 | 预案 |
|---|---|---|
| 决赛接口 hash 变化 | smoke 的 list 404/non-JSON | C1 环境变量改路径，≤1 分钟恢复 |
| 官方模型端点不稳 | 频繁 5xx/超时 | fallback 链 + launcher 单题重试；准备期问清是否有备用端点 |
| agent 单题进程崩溃 | 汇总页状态 failed | watchdog 自动重启一次；再崩则该题放弃（不影响其他题） |
| token 失效/重发 | list 返回 code≠0 | 准备期从平台重新取，注入启动脚本 |
| 挑战期想改一个参数 | 手痒 | 不行，成绩作废。所有参数必须在准备期可配置 |
| 提交返回"比赛已结束" | 平台关闸 | 正常回喂 isError，agent 不会死循环（9/10 已实测验证） |
| 笔记本断电/死机 | 录屏中断 | 重启→文件名备注中断时间→续录；launcher 重跑未完成题 |
| 网络抖动 | 工具报 ECONNRESET | 客户端已归入可重试网络错误；附件下载失败 launcher 重试 |

## 七、红线自查（每次上场前 30 秒过一遍）

- [ ] 挑战期手不碰电脑（含"就帮它重启一下"——不行，watchdog 干）
- [ ] 录屏开着、文件名规范、中断已备注
- [ ] 环节一/赛道一没用任何模型辅助
- [ ] 没有跨队交流（线上/线下都没有）
- [ ] 没有对比赛服务器/他人主机发起干扰性操作（agent 的 exploit 只打题目靶标——launcher 的 prompt 里要写明靶标边界）
- [ ] 16:00 平台结束即停手
- [ ] WriteUp 已在 30 分钟内提交

## 附：9/10 实测基线（用于校准预期）

| 维度 | 实测 | 决赛推算（30min 窗口） |

| web 题 | 2'27" | 2–4 题可解 |
